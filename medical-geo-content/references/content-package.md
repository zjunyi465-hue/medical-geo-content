# 内容附属交付

本文件用于摘要、标题、图表、链接方案及按需网页字段。它们服务正文审阅和后续内容使用，不构成上传、发布、网站修改或监测授权。用自然语言交付即可；项目需要保存状态和资产时，可填 [附属交付模板](../assets/content-package-template.json)。这个辅助文件不由现有五文件检查器校验。

## 触发与最小交付

| 项目 | 何时做 | 要保存的实际内容 |
|---|---|---|
| 最终标题、标题方案 | 文章全文交付默认提供；用户已定题或只改指定部分时保留其范围 | 最终标题及必要的备选角度/取舍；不设统一备选数量 |
| 简短摘要 | 文章全文交付默认提供；用户只要正文可省略 | 主问题、有条件的方向和文章提供的信息，不新增事实或结果承诺 |
| FAQ、目录 | FAQ能补足未解决的相关疑问，或文章较长且目录能帮助定位时 | 问答或目录；避免重复正文和固定问答数量 |
| 表格/图示方案 | 比较、流程、部位/关系等用图表能明显帮助理解时 | 用途、放置位置、内容/标签、依据与待复核项；不为了图数而加图 |
| 图片资产 | 用户要求或已授权生成/使用图片，且有可用宿主工具与必要来源时 | 实际文件/URL、图注、alt、来源/权利范围及核验状态 |
| 相关链接 | 读者需要追溯依据、了解相关问题或核对机构信息时 | 实际URL、可理解的锚文字、目的与读取状态；不虚构站内路径 |
| 网页元数据/结构化数据 | 用户要网站适配、渠道支持且真实字段可用时 | 与可见正文一致的字段/标记、未生成部分及原因 |

用户只要求提纲、短说明或局部改字时，不默认扩出完整附属包。附属内容放正文之外；摘要不能冒充完整文章，图表也不替代必要解释。

## 计划与资产分开

每项标明状态：`planned`（已有方案未生成）、`generated`（实际生成/写出）、`provided`（用户提供或已存在）、`pending_confirmation`（尚缺决定/权限/关键字段）、`not_requested`、`not_applicable`。生成状态不等于医学或权利审核通过。

图片/图示方案至少说明用途、正文位置、画面与标注、来源事实及限制。未生成时不填虚构文件路径或说已配图；实际生成后检查画面、文字标签和医学表达，并保存资产位置、图注与简洁alt。没有生图工具可交付方案并标未生成，不因此阻塞正文。

技术示意、一般插画、设备图片和病例结果分开。示意图不能冒充本机构设备、实际患者或治疗结果；不靠生图制造仪器参数、医院现场、医师身份或前后效果。使用用户/网页图片前核对实际权限，不把“可下载”当成获准对外使用；患者图还需真实授权、隐私及医学/发布复核。表格单元格同样需要来源，未知值不能为了版面补填。

### 实际图片的文件检查

确实交付图片文件时，用宿主可用工具检查实际格式、可解码性、宽高与文件体积；扩展名、格式声明以及按需生成的网页图片字段应与文件一致，不把下载到的HTML错误页或改后缀文件当图片。随后查看画面与标签：中文有无错字、关键内容是否被裁切、图示关系与正文是否一致。文件有效和内容正确是两个检查，查看文件头不能代替画面复读。

按用户用途选择导出与显示方案，没有统一固定尺寸、文件体积或图数。需要转换/压缩时保存新文件，保留原资产，转换后再查格式、尺寸与画面。尚无实际资产时交方案，不伪造这些检查结果；工具不可用时将未查项记入附属交付的 `review_notes`。图片方案、实际资产、医学内容与权利审核仍分别保持真实状态。此处不自动下载、转换或部署图片。

链接复制实际确认的URL。未读页面可列为待确认线索，不作支持依据；站内链接只有真实目标页面可用时生成。链接目的可以是追溯来源或补充阅读，不暗示链接存在即代表合作、认可或推荐。

## 条件性网页字段

渠道未定的通用文章不默认生成HTML/OG、canonical或JSON-LD。用户要求网站适配时，先确认页面类型、宿主支持的字段、实际发布主体及可用作者/日期/URL信息；没有资料不编字段来凑完整模板。

- 可依据正文写标题、description等内容字段，但不扩大结论，日期与身份不是文案创作字段。
- `author`只使用确实确认的作者/组织与授权信息，不从机构材料猜作者、专业身份或医师署名。
- `datePublished`使用已确认的实际发表日期，不能把今天或拟发布日写成已经发表；`dateModified`同样需要实际修改记录。尚未发布时不假装具备这些事实。
- `url`、canonical、image及社交分享图片地址来自真实页面或资产位置，缺少则省略允许缺省的字段，或把标记作为待完成方案；不填虚构域名、路径或ID。
- 结构化数据类型按实际页面内容与渠道要求选择，字段与可见正文一致。有FAQ不自动生成FAQPage；语法正确也不代表平台支持或具备展示资格。不承诺rich results、收录或推荐效果。

用明确的字段表或实际所需标记交付，并列出未生成字段及原因。若关键字段缺失使所需标记无法成立，交付可完成的内容字段与补充清单，不输出表面完整的伪数据。文本方案完成不代表网站已部署、字段已生效或平台已检测。

## 改稿后一起复查

摘要、标题、FAQ、图注、alt、表格和网页字段都要与新正文和当前来源一致。正文实质变更后，检查哪些附属内容需要重写、重核或重新生成；保留未完成状态，不把旧稿哈希下的记录套到新稿。最终交付说明正文、已写附属内容、资产方案、真实资产与仍需确认的事项。

将每项附属内容独立读一遍：离开正文后，是否仍明确对象、条件、时间和机构归属？不能把“在特定人群、特定随访下的观察结果”压成“人人有效”，把一般医学解释压成本机构疗效，或把待确认配置写进标题成为现行保证。FAQ新增的医学回答和图表新增的数字也需相应依据，不能用正文哈希一致代替支持检查。为短标题压不下必要条件时换角度，不靠正文或免责声明事后挽救夸大的标题。
