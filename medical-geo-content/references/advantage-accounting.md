# 优势解释与比例核算

## 先确定使用者的目标

通用 Skill 不预置机构、营销点、统一稿件篇幅或优势比例。使用者提供本次机构、允许使用的资料/营销点及写作目标；已有明确输入直接沿用。未指定篇幅的完整问题文章按编辑参考采用可调整的工作目标，用户短文或已给长度优先。用户明确要机构优势稿时，不能仅完成科普后加一次机构名。

将每条营销点记入 `task.writing_brief.marketing_points`：`id`、使用者提供的 `text`、对应 `claim_ids`。营销材料里的原说法可以登记，但不自动成为正文事实；正文用的主张仍需经过来源阅读、范围限定与状态检查。不把所有营销点强行用完，优先选能回答当前读者顾虑且有支持的内容。没有营销点依据时说明具体缺口，不自行借用其他机构资料。

`writing_goal` 明确本次用途；`institution_role` 说明机构信息承担什么作用。用户明确比例时记录 `advantage_target`：

```json
{"minimum_ratio": 0.3, "requested_by": "user", "note": "本次使用者明确的优势解释篇幅下限"}
```

这里只演示字段写法，0.3不是默认目标。没有明确比例时填 null。0到1表示正文汉字比例，可记录用户选择的任何有效值；不能把某位用户的偏好推广为全行业要求。比例是编辑约定，不是广告安全线、临床真实性、效果或 AI 推荐概率。

## 优势段写什么

先解释当前子问题，再用实际机构事实解释有关的服务或选择信息：读者有什么顾虑、材料支持什么特点、该特点在这一需要中有什么可核查的作用、范围到哪里。应有实质解释，不能只是名称、夸赞或营销点清单。

一般医学知识仍用适用医学来源；机构服务、人员、流程和配置用实际机构资料。比如有独立沟通空间，只支持材料范围内的空间设置，不足以推导所有检查在一室完成、绝对隐私或疗效改善。比较、结果、临床能力、便利性和当前服务承诺需要各自依据，不能靠“可能有助于”扩张。

正文保留必要的材料归属及读者理解所需的限制。待复核项另存不等于隐去利益关系。医学与发布状态继续按 [医学与发布复核](medical-review.md) 处理。

## 可追溯片段与正文边界

在 `review.advantage_review` 保存下列可选扩展，schema_version 仍为1.0：

```json
{
  "counting_method": "han_body_v1",
  "body_range": {"start_line": 3, "end_line": 20},
  "spans": [{
    "id": "A1", "line": 8, "start_utf16": 0, "end_utf16": 14,
    "excerpt": "机构资料列有独立的沟通空间。",
    "claim_ids": ["I1"], "marketing_point_ids": ["MP1"],
    "reader_need": "希望了解沟通安排", "explanation": "说明材料支持的空间特点，后文按依据解释适用范围",
    "scope_check": "checked"
  }],
  "semantic_review": {"status": "model_checked", "note": "逐段检查机构事实、读者关联和边界，另列未解决项"}
}
```

示例位置仅演示格式，实际列偏移必须由真实草稿求得。`line`为1起始行号，`start_utf16`从0起，`end_utf16`右端不含。列位置是 JavaScript UTF16 单位；增补汉字占两个单位、计数仍为一个汉字，不能切开。`excerpt`必须逐字等于当前行指定区间；每次改稿都要更新片段和草稿SHA256。

`body_range`覆盖从开头到末段的全部正文，首尾行均包含；标题、小标题、来源列表、末说明和免责声明不作为正文分母。范围内部的Markdown标题由工具自动排除。来源列表和末说明放范围外，不通过缩窄范围漏掉一般科普段来提高比例。正文边界由写作者和审读者逐段确认，工具不能自动识别。

这里的免责声明指独立末说明；问题解答中的必要适用条件、医学风险和限制仍计入正文，不能移出分母。篇幅记录与优势比例使用同一范围和`han_body_v1`函数。没有比例目标时，也可单独用`draft-tools.mjs`核算正文篇幅；没有声明范围不能自动区分末说明和正文。

每个优势片段按句或子句记录，关联本次营销点和正文主张，至少一条主张由实际机构材料支持。一个段落混有一般科普、机构优势和免责时，只选择其中有依据的优势解释句/子句；不得把整个混合段落标成优势。一般科普、机构名出现、营销口号、免责声明、来源标签、重复句子不纳优势分子。没有品牌名但清楚解释该机构特点的片段可以记录，名称出现本身不能让整段合格。

`reader_need`和`explanation`说明实际关联，不进入比例。`scope_check`为checked或needs_review；待核范围片段保留但不纳目标分子。`semantic_review.status`为pending/model_checked/human_checked，note记录实际逐段审读观察；模型不得伪造人工状态。超过200汉字的单片段会提示重点审读，这只是检查提示，不是统一段落长度上限或质量分数。

## 实际计数及解释

运行 `node <skill-root>/scripts/check-task.mjs <task-folder> --json`，报告的 `advantage_metrics`包括正文汉字、声明片段汉字、范围已检查片段汉字、比例、用户目标与目标状态。

`han_body_v1`数Unicode Script=Han的码点，一个汉字计一；不数标点、数字、Latin字母。正文范围内去Markdown标题、代码围栏及内容、独占行HTML注释、引用式链接定义；保留链接的可见文字，去链接URL、图片Markdown、完整HTML注释及形如 `[来源：I1,M1]` 的来源ID标签。正文宜用普通Markdown段落/列表；复杂HTML、嵌套链接、特殊Markdown渲染需另行核算并说明，不把此有限解析器当完整浏览器。

无目标时状态not_set；语义审读pending时状态pending_semantic_review；其余为met_by_declared_spans或below_target。结构或片段有错误时metrics为null。只有checked范围片段进入目标分子，重叠区间报错而不重复计数；正文无汉字不能计算。计数不按机构关键词推断段落，因此重复名称不能自动提高优势计数。

工具只接受并检查写作者声明的片段。`met_by_declared_spans`只表示这些片段的算术结果，不认证其真实语义、来源支持、完整性、文风、医学、合法性或效果。即使退出0仍需读报告warnings并完整阅读全文。若模型或人工审读发现误标，拆分或删去片段后重算；不能为了目标把一般科普、免责或大段文字标成优势。未达到目标时，补有依据且关联读者需要的解释；证据不足则明确未达到及原因，不能编造或更改审核状态凑比例。
