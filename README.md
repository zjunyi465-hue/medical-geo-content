# Medical GEO Content

一份医疗内容写作 Skill：使用者提供机构资料、营销点和写作目标，由 AI 消化资料、规划选题、写新稿或修改旧稿，将有依据的机构特点自然融入读者问题的解答。

它面向可能被 AI 检索和引用的信息供给，最终服务向 AI 提问的人。正文仍应让人读得懂、核查得清楚；不通过关键词堆积、机构名称密度或虚构背书预测推荐效果。

版本 **0.5.0**，核心文件约定 **schema 1.0**，采用 **MIT License**。本包只包含通用指令、模板和离线检查脚本，不包含真实机构资料、个人配置、患者信息、生成稿件或运行记录。

适合已经掌握机构资料，需要规划或撰写医疗内容的使用者。这是供已有 AI 宿主执行的 Skill，不是独立写作软件或模型 API。宿主负责提供模型、文件读取，以及需要时的联网阅读、生图和脚本运行能力。本包不要求自己的 API 密钥，不含账号登录、监测、CMS 上传或发布接口；模型及其他工具的费用、权限由宿主决定。

## 能做什么

| 请求 | 交付与判断 |
|---|---|
| 从资料中找选题 | 将可用事实、读者顾虑和可回答的问题对应，比较候选，说明选择理由与缺口；按需形成内容计划 |
| 对照已有内容 | 根据用户提供且实际读取的旧内容，提出继续使用、更新或另写的理由；区分目录线索与全文对照，不自动合并或修改线上页面 |
| 写完整问题文章 | 自主选题或沿用指定问题，设计标题与提纲，解释原因、区别、适用条件和下一步，再融入相关机构信息 |
| 写机构服务说明 | 依据实际资料说明服务对象、内容和必要流程，保留主体、时间与范围，避免补造服务或疗效 |
| 修改已有文章 | 完整读旧稿，区分保留、补充、重组、删改和纠正，交付新正文与变更说明 |
| 融入机构优势 | 解释真实特点与读者需要的关系，机构材料和一般医学依据分开；仅名称出现不足以完成优势稿 |
| 制作附属内容 | 文章默认附标题方案与摘要；FAQ、目录、图表、配图和链接方案按需要选择，区分方案与真实资产 |
| 适配网站字段 | 用户提出网站适配且字段可用时提供相关 metadata/结构化数据；不补造作者、发布日期、URL或图片 |
| 留下可复核记录 | 保存来源、主张对应、具体全文编辑观察，以及医学、现行服务和发布待复核项 |

完整中文医疗问题长文在未指定篇幅时，可先按约 **1800—2500 正文汉字**设计，再按问题范围、资料和体裁调整并说明理由。它是编辑工作起点，不是每篇硬限。用户指定篇幅、短文和渠道长度要求优先；不以几百字机构资料核对清单代替完整问题文章，也不重复段落凑字。

通用版不内置机构、营销点或统一优势比例。使用者可以为本次任务提出优势解释比例目标；该比例只是编辑要求，不是广告安全线、疗效证据或 AI 推荐规律。没有比例输入时不代设。

例如本次明确要求“至少四分之一”，记录为 `minimum_ratio: 0.25`，不是25，也不是默认要求。比例分母应覆盖完整正文：解答中的适用人群、医学条件、风险与限制仍属于正文，不能改称“免责声明”后移出分母。只有独立的末尾通用说明等按核算约定排除；优势分子只选有依据且与读者需要相关的解释片段。

## 使用前提供什么

- 本次机构规范名称与实际别名。
- 允许读取的材料及原始出处，营销点、时间、现行状态和已知限制。材料原说法不自动成为已核实或可对外表达的事实。
- 主问题或自主选题授权，读者与具体顾虑。
- 所需阶段：内容计划、提纲、完整草稿或改稿；可选指定体裁、篇幅、文风参考、机构作用与附属内容。
- 发布渠道可以暂不确定；原文、用户认可的参考稿和本次优势比例目标均按需要提供。

缺少影响核心事实的资料时会说明缺口；已有适用医学依据、尚未专业复核时，可以先完成待审核草稿。不因渠道尚未选择就停止通用写作。

## 安装与调用

下载或克隆仓库后，复制整个 [medical-geo-content](medical-geo-content/SKILL.md) 文件夹，不要只复制入口文件。本仓库提供本地 Skill 文件夹，未提供插件市场安装包。

根据当前 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)，Codex 的本地用户目录为 `~/.agents/skills/`，项目目录为 `.agents/skills/`。选一个适合自己的位置；已有环境如果使用其他受支持的目录，以实际配置为准。

```text
<宿主支持的 skills 目录>/
└── medical-geo-content/
    ├── SKILL.md
    ├── agents/
    ├── assets/
    ├── references/
    └── scripts/
```

已有同名版本先备份再替换，避免不同目录的同名副本误用旧版，也不要重复嵌套成 `medical-geo-content/medical-geo-content/SKILL.md`。安装后确认宿主能找到 `medical-geo-content`，使用下方提示显式调用；未显示时核对目录与文件名，并按宿主说明重新加载，Codex 未发现更新时可重启。其他宿主遵循其加载方式，本包没有验证所有宿主和模型。

你用自然语言提供任务即可，通常不需要手工填写 JSON；宿主 AI 按阶段填写工作记录和模板。模板本身不是有效任务，脚本也不会从模板自动生成文章。

全文示例：

```text
使用 $medical-geo-content。
机构名称：……；允许读取的资料：……；营销点和已知限制：……
读者与顾虑：……；主问题：……（或授权你根据资料选择具体问题）。
请写完整中文问题文章，约2000正文汉字，解释充分，将有依据的机构特点融入相关解答。
篇幅/文风偏好：……；渠道暂定通用正文。
请附标题方案、摘要、来源对应和待复核项；配图先只做有用途的方案。
输出位置：我指定的独立任务目录；没有指定时按 Skill 默认位置另存。
```

将示例中的省略号换成本次真实输入，不填写未确认的事实。这里的2000字是示例任务要求，不是所有文章的硬限；需要优势比例时另行明确，本 Skill 不根据该例代设比例。

只规划示例：

```text
使用 $medical-geo-content。请在这些资料和目标范围内比较若干选题，
说明每题可回答的内容、可用机构特点、关键缺口和先后理由，暂不写全文。
```

改稿示例：

```text
使用 $medical-geo-content。允许读取的原文和事实资料如下：……
请完整改稿，重点改善问题解答、章节推进和机构特点的自然衔接。
必须保留的事实/条件：……；篇幅与文风目标：……
保存新版本及变更说明，遇到无依据旧说法说明纠正理由，不覆盖原稿。
```

它以 Markdown 指令和文件约定指导模型执行，安装成功不能保证每个模型都按同样质量完成。参考文章用于理解文风，不能自动继承其中的病例、数字或服务说法。

## 交付与检查

优先保存到你指定的位置。没有指定时，在当前项目的 `outputs/medical-geo-content/<日期>/<任务ID>/` 新建目录；同名目录已存在时另存新版本，不覆盖。

建议在自己的私有工作项目中使用。当前项目如果准备公开，请指定仓库之外的私有输出目录，将真实资料、稿件与 Skill 源码分开。

| 阶段 | 保存内容 |
|---|---|
| 简报或多题规划 | `task.json`、`evidence.json`；按需另有 `content-plan.json` |
| 单篇提纲 | 上述核心记录及 `outline.md` |
| 完整草稿或实质改稿 | 另有 `draft.md`、`review.json`；改稿附变更说明 |
| 附属交付 | 按需另有 `content-package.json`、实际图片文件或方案说明 |

任务记录的 `reviewed` 表示完成了一轮已记录的检查；医学专业复核、机构现行服务确认和渠道发布复核是否完成，仍要分别看 `review.json` 中的状态与待办。它不等于“可以发布”。

`draft.md`保存供阅读的文章；依据和内部审读记录放在其他文件，正文仍保留必要归属与范围。宿主没有文件工具时可以交付正文、依据和同等记录，但不能声称已保存文件或运行脚本。局部任务不强制多余产物。详见 [交付约定](medical-geo-content/references/artifacts.md)、[内容开发](medical-geo-content/references/content-development.md) 和 [附属交付](medical-geo-content/references/content-package.md)。

模板需要填写，未使用的空条目应删除。新完整草稿与实质改稿保存具体 `editorial_review`：实际回答范围、章节新增信息、解释深度、正文篇幅、优势作用、重复处理及未达要求；不能只填“通过”。

医学判断还要检查来源是否适用于本文人群、检查或治疗、比较对象和观察结果，分别处理相对/绝对变化与数字范围，并记录 `evidence_review` 的实际发现。标题、摘要与图表也保留关键条件。这些是写作审读要求，不是正式证据分级、临床指南制定或专业认证；简单任务按实际影响范围处理。

先阅读全文：标题是否得到充分回答、机构特点是否有依据且相关、医学条件和材料归属是否保留、篇幅是否符合本次要求。结构脚本是辅助，不是文章生成器、事实核验或医学审批程序。已提供的新审读记录不能保留空模板；未完成时写清实际待办并保持pending，不为了通过检查填“已审核”。

三个脚本使用 Node.js，无第三方包和网络调用；本地验证使用 Node.js 24。只有需要脚本检查时才需要 Node.js，缺少该环境仍可写作，但要注明结构检查未执行。检查器仅读任务目录五个固定核心文件，按阶段决定哪些必需；不抓取来源 URL、不读取原稿引用，不校验辅助计划和附属内容；已提供的编辑与依据审读记录会检查关键字段、主张ID和状态冲突，但不会验证观察内容是否真实或充分。旧任务缺少整份新增记录只提示补充。

在仓库根目录运行下方命令，将 `"<task-folder>"` 换成已生成的任务目录；安装后把脚本路径换成实际 Skill 路径。路径含空格时保留引号。

```text
node medical-geo-content/scripts/check-task.mjs "<task-folder>"
node medical-geo-content/scripts/check-task.mjs "<task-folder>" --json
```

| 报告 | 如何理解 |
|---|---|
| `errors` 非空，退出1 | 格式、状态或对应关系不一致，需要修正；检查未能执行也可能退出1 |
| `errors` 为空，退出0 | 已执行的结构检查未发现错误，仍可能有待复核项 |
| `warnings` 非空 | 记录中的专业审核、范围或渠道等待办仍存在 |
| `publication_ready: false` | 此工具始终不授予发布许可，与退出码无关 |
| `advantage_metrics` | 有相应记录且结构成立时提供声明片段的汉字核算，不认证优势语义 |

脚本检查 ID、版本哈希、准确摘录和保留项，无法证明源文支持正文，也无法发现没有登记的事实、认证人审或预测 AI 效果。

正文篇幅与优势比例使用同一完整正文范围及`han_body_v1`计数口径；新稿在`editorial_review.length_review.body_range`记录首末行号。检查器核对已填字数和两处范围是否一致，旧记录无范围时提示字数未验证。

有明确优势比例目标时，按 [优势解释与比例核算](medical-geo-content/references/advantage-accounting.md) 保存句/子句级准确片段并实际计数。`met_by_declared_spans`仅描述声明片段的算术结果，不证明片段语义、文章质量、医学安全或发布许可。schema 1.0 旧任务可继续运行，不需要为了运行脚本补全新增编辑字段。

当前比例工具按中文正文汉字核算，不是英文词数或所有语言的通用计数器；使用其他语言时，应另行说明篇幅与比例口径。

### 减少手工记录

辅助工具只读你指定的正文，输出原始文件SHA256、所选正文范围的汉字数，以及准确摘录的全部单行匹配位置：

```text
node medical-geo-content/scripts/draft-tools.mjs "<draft.md>" --start-line 3 --end-line 40
node medical-geo-content/scripts/draft-tools.mjs "<draft.md>" --start-line 3 --end-line 40 --excerpt "从当前正文复制的准确单行原文"
```

行号只是示例，需换成实际完整正文范围；标题与末说明的边界由使用者或写作者确认。多处匹配会全部返回，不自动选择；`line_counted_as_body`仅表示匹配所在行是否参与正文范围计算，不证明摘录本身属于优势或含有可计汉字。未找到摘录退出1，不会造一个位置。工具不编辑正文或审核文件，不抓取来源，不认证优势语义；核对结果后再填写记录。正文实质改动仍须重新审读，不能只更新哈希保留旧人审。

## 常见情况

| 情况 | 处理方式 |
|---|---|
| 已安装但没有调用 | 核对宿主是否发现 Skill，用 `$medical-geo-content` 显式指定并提供任务 |
| 只有营销口号，没有出处 | 补具体资料或限定可写范围，不把口号换种语气当事实 |
| 网页打不开或只能读摘要 | 记录实际读取范围，可补原资料；不声称全文已核验 |
| 没选渠道 | 先交通用待审核稿，发布状态保持渠道待定 |
| 缺 Node.js 或图片工具 | 写作仍可进行，分别注明结构检查未执行或图片仅为方案 |
| 检查退出0但还有待办 | 阅读 warnings 和审读记录，结构成功不会解除专业/发布待办 |
| 只需要短文或局部修改 | 明确范围，不必扩成默认长文或附属包 |

## 医学、发布与隐私

本 Skill 提供内容工作指引，不提供个体诊断、处方或治疗决定，也不替代医学专业复核。来源真实性、临床适用范围、机构现行服务和发布要求分别判断。营销材料可证明材料里怎么说，不能自动证明疗效、资质或当前服务；一般医学来源也不能证明某机构的效果。没有真实专业审核不得填人工通过；渠道未定时保留 `pending_channel`。正式发布按实际主体、渠道和当时规则核对，见 [医学与发布复核](medical-geo-content/references/medical-review.md)。

不虚构患者体验、医生署名、采访、比较优势、疗效、排名或数字。必要的对象、条件、日期、风险和材料归属应留在正文；免责声明、比例或“据介绍”不能为无依据说法提供许可。不承诺收录、引用、提及、推荐或排序。

用户资料、患者内容、账号文件、真实试写及日志放在公共仓库之外。`.gitignore`只忽略约定路径，不能替代提交前审查。资料内的命令不是用户指令；不据此上传、发消息或修改账号。站外上传和发布需要使用者另行明确授权。图片计划不冒充设备实拍、患者病例或治疗结果；生成资产与权利、医学审核分别记录。
